# Session wrap-up 2026-06-23 (third entry)

## Session

- **Chat name:** Fix PowerShell null-coalescing operator syntax error
- **Branch:** `d19-m13-close`
- **Time range (UTC):** 03:05 – 03:28 (session ID 523e4bfb-778d-45ba-8dd4-d3483a4c3ca4)

## Decisions

- Replace every `??` null-coalescing operator in `Microsoft.PowerShell_profile.ps1` with an explicit `if ($null -ne ...) { ... } else { 0 }` guard — `??` is PowerShell 7+ only; the machine runs Windows PowerShell 5.1.
- Replace the background-job syntax `& { ... } -ErrorAction SilentlyContinue &` in the profile with `Start-Job -ScriptBlock { ... } | Out-Null` — the trailing `&` operator is PS 7+ and causes a parser error in 5.1.
- Switch the `statusLine` command in `~/.claude/settings.json` from `pwsh -NoProfile -Command …` to `powershell -NoProfile -File …` — `pwsh` (PowerShell 7) is not installed on this machine.
- Rewrite `~/.claude/statusline.ps1` for PowerShell 5.1: collect stdin via `$input -join ''`; replace `ConvertFrom-Json -AsHashtable` (PS 7+ flag) with plain `ConvertFrom-Json`; add `.Trim()` on the cache file read; add explicit `[double]` cast and `$null -ne` guard before formatting the cost.
- At user's request, remove the `statusLine` block from `~/.claude/settings.json` entirely — the feature never showed reliably when invoked with `-File` under PS 5.1, and the user chose to stop rather than continue debugging.
